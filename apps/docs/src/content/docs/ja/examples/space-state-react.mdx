このパッケージは関数1つ・約10行で、ロジックを一切持ちません。ソースを見せても「本当にこれだけ？」
以上のことは分からないので、代わりに**レンダリング回数**を出します。同じ人に対して `typing` を
2回押してみてください。2回目は再レンダリングされません — store が同一の state 参照を返し、
`useSyncExternalStore` が bail out するからです。

<SpaceStateReactDemo client:only="react" />

## 試してみること

- **chat** を何回か押す。メッセージのたびに新しい state になるので、`<ChatPanel />` は毎回
  再レンダリングされ、回数が received と一緒に増えていきます。
- **typing (same person)** を連打する。最初の1回だけ再レンダリングされ（`typingUsers` に名前が
  加わるため）、それ以降は `messages received` だけが増えて回数は動きません。この差がこのページの
  すべてです。
- `typing` を何回か押したあとで **chat** を押す。入力中表示が消えてパネルが再レンダリングされます
  — 本当に変わったときはちゃんと通ります。

## 裏で動いているコード

```tsx
import { createSpaceStore } from '@insession/space-state';
import { useSpaceState } from '@insession/space-state-react';

const store = createSpaceStore({ selfName: 'you', t: (k) => k, getPresence: () => 'active' });

function ChatPanel() {
  const state = useSpaceState(store);
  return <ul>{state.chatLines.map((line) => <li key={line.id}>{line.text}</li>)}</ul>;
}
```

統合はこれで全部です。bail out の挙動はここで実装されているわけではありません — store が
`useSyncExternalStore` の契約（何も変わっていなければ `getState()` は同一参照を返す）を守っている
ことから来るもので、このパッケージはそれを邪魔しないだけです。

シグネチャと、`getServerSnapshot` を渡さない理由については
[パッケージのリファレンス](/ja/packages/space-state-react/)を参照してください。
