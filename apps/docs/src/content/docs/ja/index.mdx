## 最短路

どの extension もそのまま渡せる記述子を持っているので、サーバー側の機能が1行で動きます。
返ってきた effect をどう扱うかは[はじめかた](/ja/getting-started/)を参照してください。

```ts
import { createSpace } from '@insession/space';
import { pomodoroExtension } from '@insession/extension-pomodoro';

const space = createSpace({ extensions: [pomodoroExtension()] });

space.dispatch('pomodoro', 'start'); // -> [broadcast, schedule-timer]
```

<p class="dep-note">
  パッケージ間の依存は1本もありません。<code>space</code> / <code>space-state</code> /
  <code>ws-resilient-transport</code> / <code>extension-pomodoro</code> /
  <code>extension-whiteboard</code> / <code>extension-watch-party</code> /
  <code>extension-chat</code> はそれぞれ独立しています — <code>space</code> は既存4つの状態機械が
  もともと満たしている形（<code>defaultState</code> / <code>reduce</code> / <code>restore</code> /
  <code>persistState</code> 等）を契約として言語化しただけなので、状態機械の側から
  <code>space</code> を import する必要も、<code>space</code> の側から特定の状態機械を import する
  必要もありません。バイトを運ぶことと状態を持つことを意図的に切り離してあるので、どれか1つだけを
  採用できます。React で使う場合も、入れるバインディングのパッケージはありません。
  <a href="/ja/examples/react-binding/">自分で書く1行</a>がフックの全部です。
</p>
